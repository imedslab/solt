class solt.core.BoundingBoxes(boxes=None, height=None, width=None, fmt='voc', labels=None, unclipped=None)[source]¶

Bases: object

Bounding boxes, optionally with a label for every box.

The boxes are stored in the VOC format: x_min, y_min, x_max, y_max, in continuous pixel coordinates, i.e. the image spans [0, width] x [0, height], and the pixel i covers [i, i + 1). The transforms move the corners of the boxes, and the result is the box enclosing the transformed corners. DataContainer clips the boxes to the image after every transform, since the content outside of the image is lost. At the end, Stream drops the boxes, which became too small or are mostly outside of the image (see Stream), together with their labels.

Parameters:

  • boxes (numpy.ndarray or list) – Boxes Nx4 in the format fmt.

  • height (int) – Height of the coordinate frame.

  • width (int) – Width of the coordinate frame.

  • fmt (str) – Format of boxes: 'voc' (x_min, y_min, x_max, y_max), 'coco' (x_min, y_min, width, height), 'cxcywh' (x_center, y_center, width, height) or 'yolo' (x_center, y_center, width, height, as fractions of the image size).

  • labels (numpy.ndarray or list or None) – Labels of the boxes, one per box.

  • unclipped (numpy.ndarray or None) – The boxes Nx4 in the VOC format before clipping to the image, if they differ from boxes. SOLT tracks them to measure, which fraction of the boxes is outside of the image.

class solt.core.DataContainer(data, fmt, transform_settings=None)[source]¶

Bases: object

Data container to encapsulate different types of data, such as images, bounding boxes, etc.

The container itself is iterable according to the format. Data container assumes the same coordinate system for all the items it is storing. For instance, the behavior shown below is not supported:

from solt.core import DataContainer
import numpy as np

img1 = np.ones((100, 100, 3), dtype=np.int32)
img2 = np.ones((110, 110, 3), dtype=np.int32)
trf_img = DataContainer.from_dict({'images': (img1, img2)})
Parameters:

  • data (tuple) – Data items stored in a tuple

  • fmt (str) – Data format. Example: ‘IMMM’ - image and three masks. See solt.constants.ALLOWED_TYPES.

  • transform_settings (dict or None) –

    Settings for each data item. At this stage, the settings include padding and interpolation, and for distance maps also the fill value. The key in this dict corresponds to the index of the element in the given data tuple. The value is another dict, which has all the settings. Segmentation masks have nearest neighbor interpolation by default, this can be changed manually if needed. Example: transform_settings={0:{'interpolation':'bilinear'}, 1: {'interpolation':'bicubic'}}

    Bounding boxes ('B') are clipped to the image, when a container is created, i.e. after every transform.

    Distance maps ('D'), e.g. signed distance fields, are floating point arrays HxW or HxWxC. They have bilinear interpolation by default, and their values are rescaled when a transform changes the scale of the image (the rescaling is exact for similarity transforms and approximate otherwise). The zero padding would create a false object boundary, so a distance map is padded with its fill value instead, if it is set, and with its edge values otherwise. Example: transform_settings={1: {'fill': 100.0}}

static from_dict(data)[source]¶

Creates a data container from a dictionary.

If data is a dict, then the solt.data.DataContainer will be created so that the image data will be stored first. Subsequently, multiple images under the key images will be stored. The same applies to masks (first mask and then masks), distance maps (distance_map and distance_maps), labels (label and labels), the keypoints (keypoints and keypoints_array) and the bounding boxes (bboxes and bboxes_array). The bounding boxes must be stored in solt.core.BoundingBoxes objects. You must use solt.data.KeyPoints object here. Labels will always be stored last.

For example, if the input dict looks like this: d = {'label': l1, 'image': i1, 'mask': m1} or d = {'mask': m1, 'image': i1, 'label': l1}, the DataContainer will convert this into sld.DataContainer((i1, m1, l1), 'IML'). The order of the types is images, masks, distance maps, keypoints, bounding boxes and labels.

More complex case:

d = {'image': i1, masks: (m1, m2, m3, m4), 'labels': (l1, l2, l3, l4, l5),
'keypoints': solt.core.KeyPoints(k, h, w)}
dc_from_dict = solt.core.DataContainer.from_dict(d)

will be equivalent to

dc = solt.core.DataContainer((i1, m1, m2, m3, m4, solt.core.KeyPoints(k, h, w), l1, l2, l3, l4, l5),
'IMMMMPLLLLLL').

Please note, that when you create DataContainer using such a simplified interface, you cannot setup the transform parameters per item. Use a proper constructor instead.

Parameters:

data (dict) – Data stored in a dictionary

Returns:

out – Newly instantiated data container object

Return type:

sld.DataContainer

distance_scale()[source]¶

Returns the factor, by which the transform changes the distances around the image center.

It is the square root of the area change, i.e. of the Jacobian determinant of the transform. For a homography H, it equals to det(H) / w ** 3, where w is the homogeneous coordinate of the transformed center. This is exact for the similarity transforms (rotation, uniform scaling and translation), and an approximation otherwise.

class solt.core.Stream(transforms=None, interpolation=None, padding=None, optimize_stack=False, ignore_fast_mode=False, shuffle=False, in_place=True, max_bbox_area_loss=0.9, max_bbox_outside=0.5)[source]¶

Bases: Serializable

Stream class. Executes the list of transformations.

The stream can be called directly on a dict of items, which get converted into a DataContainer. Note that the DataContainer assumes the same coordinate system for all the items it is storing. For instance, the behavior shown below is not supported for any stream:

import solt.transforms as slt
import numpy as np

trf = solt.Stream([slt.Resize(resize_to=(50, 50)),
                       slt.Flip()])
img1 = np.ones((100, 100, 3), dtype=np.int32)
img2 = np.ones((110, 110, 3), dtype=np.int32)
trf({'images': (img1, img2)})
Parameters:

  • transforms (list or None) – List of transforms to execute

  • interpolation (str or None) – Stream-wide settings for interpolation. If for some particular transform your would like to still use its own mode, simply pass (<interpolation_value>, 'strict') in the constructor of that transform.

  • padding (str or None) – Stream-wide settings for padding. If for some particular transform your would like to still use its own mode, simply pass (<padding_value>, 'strict') in the constructor of that transform.

  • optimize_stack (bool) – Whether to run transforms stack optimization. It can only be useful if many matrix transformations are in a row.

  • ignore_fast_mode (bool) – Whether to ignore the fast mode. This option enables full geometric transforms. It always overrides the setting of the matrix transforms, including the ones in nested streams.

  • shuffle (bool) – Whether to shuffle the transforms before applying them.

  • in_place (bool) – Whether the transforms may modify the input arrays in place. Transforms do not copy the data unless necessary, e.g. CutOut writes into the image it receives, and Crop returns a view. If False, the stream copies the input data once before applying the transforms, so the original arrays stay unchanged.

  • max_bbox_area_loss (float or None) – Bounding boxes are dropped (with their labels), if their share of the image area at the end of the stream is smaller than at its start by more than this fraction. 0.9 by default, i.e. the boxes, which became more than 10 times smaller relative to the image, are dropped. Resizing the whole image does not change the share, while e.g. Scale in the same frame or Pad decrease it. None disables this check.

  • max_bbox_outside (float or None) – Bounding boxes are dropped (with their labels), if more than this fraction of their area is outside the image at the end of the stream. 0.5 by default. None disables this check.

Notes

DataContainer clips the bounding boxes to the image after every transform, and tracks the unclipped ones. At the end, the stream drops the boxes, which exceed max_bbox_area_loss or max_bbox_outside, and the boxes fully outside of the image, also if both checks are disabled. Nested streams leave this to the outermost one.
